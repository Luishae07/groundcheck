GROUNDCHECK

API

Real weather-balloon measurements from around the world, free and read-only. No sign-up needed. An optional free key raises the limit a lot. Back to the weather app.

Quick start

curl {BASE}/api/data

That returns every recent ground-level reading as JSON, newest first. Without a key you get 30 requests per 60 seconds per address.

Get a free key (13,000 requests per 10 seconds)

curl -X POST {BASE}/api/keys/new

Prefer a button to a command? Get a key on this page.

curl {BASE}/api/data -H "X-API-Key: YOUR_KEY"
curl "{BASE}/api/data?key=YOUR_KEY"

Endpoints

GET/api/data

All current ground-level readings, newest first. Only temperatures at or above 0 °C and sensor heights up to about 980 m are included. With a key, your key's settings filter and reshape the answer.

QUERY/api/weather

The temperature at any coordinates, from the nearest radiosonde that measured near the ground in the last 19 hours. Send the coordinates in the body. Details. GET /api/weather?lat=…&lon=… gives the same answer.

GET/api/quota

Your coins left today. Send your key; without one you see the balance of your address.

POST/api/keys/new

Makes a free key on the spot: {"api_key": "…", "limit": "13000 requests / 10s"}.

GET/api/keys/KEY/stats

What your key has used. The key itself is the password.

POST/api/keys/KEY/settings

Changes the settings of your key, for example {"label":"mine","min_lat":47,"max_lat":55.1,"max_age_hours":48}. Also pauses or resumes it with {"paused": true}.

POST/api/keys/KEY/revoke

Deletes your key for good.

GET/api/keys/settings/schema

The list of all 30 settings with their types and defaults.

Limits and errors

Over the rate limit, or out of coins, you get 429 with a Retry-After header. A paused key gets 403. A key that does not exist is treated like no key at all, so you get the lower limit. Everything is GET, POST or (for the weather call) QUERY JSON, and any website may call it (CORS is open).

Coins

Every answer from /api/data and /api/weather costs coins, a little like an AI API: the more you ask and the longer the answer, the more you pay. 1 coin pays for 250 MB of answers.

You getCoins
A new key10
Every day (up to 30 stored)+10
Without a key1 per address and day
An app with 100 users (see below)+100, once

Price: every byte you get back costs 4 units and every byte you send costs 1 unit (1 coin = 1,000,000,000 units). A request costs at least 1,000 units. Errors cost nothing.

RequestAboutPer coin
/api/weather0.000001 coin1,000,000 requests
/api/data (gzip, about 5 MB)0.02 coinabout 46 downloads
/api/data (no gzip, about 42 MB)0.17 coinabout 6 downloads

Ask for gzip (Accept-Encoding: gzip) and the same data costs a fraction. Each answer carries X-Quota-Cost and X-Quota-Remaining (in coins). When the balance is too low you get 429 out_of_coins.

100 users = 100 coins

If you build an app with Groundcheck data, send an anonymous id of each of your users with every request, for example a hash. Never a name or an email:

curl {BASE}/api/weather?lat=52.184&lon=13.432 -H "X-API-Key: YOUR_KEY" -H "X-Groundcheck-User: 9f2c41aa"

When your key has seen 100 different ids in one calendar month, it gets 100 coins, once. Only a short hash of each id is kept. /api/quota shows the count.

Weather at a point

Ask for the weather at any coordinates. The answer comes from the nearest radiosonde that reported a reading under 1,500 m in the last 19 hours.

curl -X QUERY {BASE}/api/weather -d '{"lat": 52.184, "lon": 13.432}'

QUERY is a read-only request that carries a body, so the coordinates stay out of the address. It works with fetch too, from any website:

const r = await fetch('{BASE}/api/weather', {
  method: 'QUERY',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ lat: 52.184, lon: 13.432 })
});
console.log(await r.json());

The coordinates can also be {"coordinates": "52.184 13.432"} or plain text 52.184 13.432. Latitude is -90 to 90 and longitude -180 to 180. Without a tool that can send QUERY, use GET {BASE}/api/weather?lat=52.184&lon=13.432.

{
  "temp": "9.3C",                          // the temperature as text
  "temp_c": 9.3,                           // the same as a number
  "radiosonde_used": "X3722285",           // the sonde (or station) the reading came from
  "coordinates_picked": "52.184 13.432",   // what you asked for
  "country_coordinates": "Germany",        // the country at those coordinates
  "distance_km": 47.0,                     // how far the radiosonde was from your point
  "humidity": 74.1,                        // percent, or null
  "pressure": 955.95,                      // hPa, or null
  "measured_at": "2026-10-23T11:48:01Z"    // UTC
}
StatusWhen
200The answer above.
400The coordinates are missing or out of range.
404No near-ground reading from the last 19 hours exists.
429Over the limit: 30 requests per 60 seconds without a key, 13,000 per 10 seconds with a key (X-API-Key). The weather call has its own count, separate from /api/data.

Over open sea, country_coordinates says none (open sea or no country). Check distance_km: the nearest radiosonde can be far away.

What a reading looks like

{
  "id": "Y0943402",                 // sonde serial, or the weather station for NOAA readings
  "time": "2026-10-12T14:08:28Z",   // UTC
  "tsunix": 1791814108,             // the same time in Unix seconds
  "temp": 12.7,                     // degrees C, never below 0
  "alt": 474.9,                     // metres above sea level
  "pressure": 959.8,                // hPa, or null
  "humidity": 90,                   // percent, or null
  "lat": 51.772308,
  "lon": 9.25355,
  "source": ["RS41", "SondeHub"]    // see "Where the readings come from"
}
FieldTypeMeaning
idstringThe sonde's serial number. For NOAA readings, the weather station's id (for example GMM00010393).
time, tsunixstring, numberWhen it was measured, in UTC.
tempnumberAir temperature in °C. Readings below 0 °C are left out.
altnumberHeight in metres. For a balloon, where the sensor was. For NOAA, the station's height.
pressure, humiditynumber or nullhPa and percent. Some sources do not report them.
lat, lonnumberPosition in degrees.
sourcearrayThe instrument or the archive it came from. The last entry names the network: SondeHub or IGRA. Readings with only an instrument name come from the live sonde.mine.nu feed.

Where the readings come from

sonde.mine.nu / zeesen.mine.nu

Live radiosonde telemetry from a volunteer receiver network, mostly in central Europe. Updated every minute. source is the sonde type, such as ["RS41"].

SondeHub

An open worldwide database of radiosonde telemetry. Groundcheck keeps the ground-level frame of each sonde every 5 hours, so it covers many more countries, with a delay of about 5 hours. source ends with "SondeHub". Thank you to the volunteers who run the receivers. sondehub.org

NOAA IGRA

The Integrated Global Radiosonde Archive: the official soundings of about 650 weather-service stations in more than 100 countries, one reading per station per day (the sounding nearest 12:00 UTC). Public domain, from NOAA NCEI. Each station is refreshed about once a week, so readings can be up to a week late. source is ["IGRA"]. NOAA IGRA

If you use the data, please credit sonde.mine.nu, SondeHub and NOAA NCEI.

Key settings

These apply only to requests that carry your key. Every setting is optional. GET /api/keys/settings/schema lists them all.

SettingWhat it does
min_lat max_lat min_lon max_lonOnly readings inside this box.
max_age_hoursOnly readings newer than this.
limit_resultsAt most this many readings.
dedupe_by_stationOne reading per sonde or station: the newest.
temp_/humidity_/pressure_/altitude_ min_threshold, max_thresholdDrop readings outside a range.
…_decimal_places, temp_round_to_integerRound the numbers.
temp_convert_unitsTemperatures in °F instead of °C.
…_hide_if_null, strip_null_fieldsSkip readings or fields that are missing.
sort_by_time_desc, pretty_print, include_metadataOrder and layout of the answer.

Example: Europe only, last 24 hours, one reading per station

curl -X POST {BASE}/api/keys/YOUR_KEY/settings \
  -d '{"min_lat":35,"max_lat":72,"min_lon":-12,"max_lon":45,"max_age_hours":24,"dedupe_by_station":true}'
